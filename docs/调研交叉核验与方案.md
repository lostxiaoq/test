**结论：Gemini 的事实部分大体可靠，营销口径的数字要打折看。** 它补上了两点本仓库调研没有覆盖的内容：
1. **滚动弧规划**（ainovel-cli）：比我原方案里「一次写完第一卷逐章细纲」更好。
2. **文剧融合**：咪咕现在的核心诉求是能改编成短剧或 AI 漫剧的 IP。这会直接影响写法，要求画面感强、冲突外化、对话驱动，每章能拆成若干分镜。

## 2. Gemini 方案的盲点

1. **完全没提 AI 合规。** 它的三套方案都默认「全自主」。2026 年行业整体在收紧 AI 创作（番茄严打，起点和七猫编辑公开表态拒收，16 家平台签了自律公约）。咪咕自己大力做 AIGC 短剧，但**没找到它对 AI 写的投稿怎么处理**。这一点必须先向编辑确认，否则写完 30 万字可能被拒签。
2. **拆书仿写的边界。** 学情绪曲线、节拍结构、钩子类型是安全的。换皮式仿写（情节和人设一一对应）属于洗稿，各平台都是红线。我们只抽象到「节拍类型 + 情绪强度」这一层。
3. **流程过重的风险。** 方案 C 把所有机制都叠在一起，第一本书容易在工程上耗死。应该先跑通一条最小闭环，再逐步加功能。

## 3. 最终建议

**流程：方案 C 的精简版**，按需逐步加功能

| 模块 | 来源 | 第一版是否做 |
|---|---|---|
| 指南针 + 滚动弧规划（每弧 15–20 章） | ainovel-cli | ✅ |
| 事实账本 + 作者真相/读者已知分离 + 每章事实提交 | oh-story / webnovel-writer | ✅（用 JSON 和 Markdown 文件，先不上 RAG） |
| 角色声线表 + 跨 2 章连续桥 | awesome-novel-studio | ✅ |
| 拆书得到节拍类型和情绪曲线（抽象层，不换皮） | harnessNovel / oh-story | ✅ 只做黄金三章和第一弧 |
| 去 AI 味脚本 lint + 对抗式删减 | oh-story / autonovel / novel-writing-framework | ✅ |
| 读者小组多人格评审、Elo 对比 | autonovel | 每弧做一次 |
| 分镜友好检查（每章能不能拆成 8–10 个可拍场景） | 咪咕文剧融合 | ✅ 写进细纲字段 |

**题材：现实底色 + 行业逆袭 + 爽文节奏。** 这个方向同时满足四件事：
- 对上咪咕扶持方向（现实题材、行业百态、咪咕杯）；
- 契合运营商用户的主流口味；
- 适合改编短剧（冲突外化、场景具体）；
- AI 能发挥资料考据的优势。

可以细化成三个候选方向，下一步各出一张选题卡：
1. 通信 / 数智行业逆袭（重生回到某个技术节点，一线视角，和咪咕「东家」的属性高度契合）
2. 非遗手艺 + 文旅商战（地方文化垂类，画面感强）
3. 体育竞技 / 大国制造（参照《冰上荣耀》的成功路径）

**体量：** 先按完本 30 万字左右规划（2 卷、约 120 章、每章 2500 字），写完存稿再按全勤节奏发布。
