# 创作流程规范（方案 C 精简版）

> 本文件是每次写作会话的**第一份必读文件**。换会话、上下文压缩之后，先读本文件，再读 `追踪/上下文.md`，就能从断点继续。
> 设计来源：滚动弧规划（voocel/ainovel-cli）· 事实账本与作者真相 / 读者已知分离（oh-story-claudecode、webnovel-writer、InkOS）· 角色声线表与跨章连续桥（awesome-novel-studio）· 拆书抽象节拍（harnessNovel）· 去 AI 味与对抗式删减（autonovel、novel-writing-framework）· 文剧融合分镜要求（咪咕平台）。

## 0. 目录

```
novel/
├── WORKFLOW.md          本文件
├── config.json          全局参数（字数、阈值）
├── 00_市场/             行业调研、访谈素材、拆书报告、选题卡
├── 01_设定/             指南针.md · 世界观.md · 人物/（人物卡 + 声线表）· 文风基准.md
├── 02_大纲/             路线图.md（卷、弧骨架）· 弧纲/ · 细纲/第NNN章.md
├── 03_正文/             第NNN章_章名.md
├── delta/               第NNN章.json（每章状态增量，交给 state_commit.py）
├── state/               权威事实账本（JSON，只能通过脚本写）
├── 追踪/上下文.md        派生的上下文卡（脚本生成，勿手改）
├── reviews/             单章审稿 · 弧审 · 读者小组
├── templates/           各类模板
└── tools/               deslop.py · chapter_check.py · state_commit.py
```

## 1. 人工拍板点（只有这几处需要作者，其余由 AI 推进）

| 节点 | 作者要做的事 |
|---|---|
| G1 选题卡 | 选定或修改选题 |
| G2 指南针 + 主角 / 核心配角人物卡 | 确认终局方向、主角动机、金手指 |
| G3 黄金三章 | 通读，亲手改写关键段落 |
| G4 每弧结束 | 看弧审报告，确认下一弧方向（可以只回一句"继续"） |
| G5 完本前 | 通读高潮章和结局，终审，如实勾选 AI 声明 |

## 2. 规划：指南针 + 滚动弧

1. **指南针**（`01_设定/指南针.md`）：终局状态、主角终极目标、3–5 条长线、规模估计（字数、卷数）。每卷结束时可以修订。
2. **路线图**（`02_大纲/路线图.md`）：全书各卷、各弧的**骨架**，每弧只写目标、弧型、预估章数。
3. **只展开当前弧**：每弧 15–20 章，写完一弧才展开下一弧的逐章细纲。展开前必须先读上下文卡和上一弧的弧审。
4. 弧型（任选并轮换）：逆袭破局弧 · 竞争对抗弧 · 危机救场弧 · 揭秘调查弧 · 经营建设弧 · 日常过渡弧（最多 3 章）。
5. **下游不反推上游**：细纲写不下去，就回去改弧纲或指南针，不在细纲上打补丁。

## 3. 单章流水线（每章必走，顺序不可跳）

```
① 写前门禁   chapter_check.py --outline 细纲  → 字段齐全才能写
② 任务书     读 上下文卡 + 本章细纲 + 前 2 章正文结尾（连续桥）+ 出场人物的 声线圣经 条目
             → 在回复中列出：must-keep（必须兑现）/ must-avoid（禁止出现、禁止剧透的真相 ID）
③ 起草       按细纲的分镜节点写，单章 2500 字左右
④ 自审       对照 6 维：一致性 · OOC（声线）· 节奏 · 爽点兑现 · 钩子 · 读者已知边界
             有 blocking 问题就回到 ③
⑤ 对抗删减   假设必须删掉 300 字：删掉的是不是解释、总结、重复？删完再补具体动作或对话
⑥ 去 AI 味   deslop.py 正文 → 0 blocking；chapter_check.py 正文 → ok
             voice_check.py → 0 违规；再用 --who 把本章出场人物的全部台词通读一遍，像不像同一个人
⑦ 记账       写 delta/第NNN章.json → state_commit.py check → commit
⑧ 提交       git commit（正文 + 细纲 + delta + state + 上下文卡）
```

## 4. 周期检查

| 周期 | 动作 | 产物 |
|---|---|---|
| 每 3 章 | 连读 3 章：节奏是否单调、场景是否重复、口水词趋势 | 有问题就当场修，不攒 |
| 每弧 | 弧审：爽点和钩子分布表、伏笔健康、人物弧光；**读者小组**四个人格（小白读者 / 行业内行 / 网文老书虫 / 咪咕编辑）各写一段评语和评分 | `reviews/弧N.md` → G4 |
| 每卷 | 全卷一致性复查，修订指南针，展开下一卷骨架 | |

## 5. 写作硬规则（咪咕档）

**结构**
- 本章必须产生一类变化：局面、权力、关系、认知（delta 的 `change_type`，脚本强制）。
- 开篇前 300 字要有事件或冲突，禁止用"站着、看着、想着"开头。
- 章末必有钩子，类型不能连续 2 章重复。爽点类型不能连续 3 章重复，也不能连续 3 章没有爽点。
- 3 章一小爽、10 章左右一个大高潮。高潮后的日常最多 2 章。
- 爽点能用"谁 + 做了什么 + 谁 + 付出了什么代价"描述。主角靠**判断正确 + 执行到位 + 专业碾压**赢，不靠运气和作弊。

**文剧融合（短剧化）**
- 每章细纲列出 6–10 个**可拍的场景节点**（地点、人物、动作、冲突），尽量少写"心理活动"段落。
- 对话驱动，对话占比 20% 以上；冲突外化成动作、物件、数字（工单、排名、告警、合同）。

**活人感**
- 行业细节必须来自 `00_市场/` 的素材库，不确定的不要写，或者写得模糊一些。
- 每个主要角色都要有声线表：口头禅、句尾习惯、说话节奏、小动作、不会说的话。
- 写具体的东西：一张工单、一台油机的噪音、一份红黑榜，而不是写"压力很大"。
- **数据要变成画面**：一段最多一个具体数字，其余用比喻和生活化的意象（沙里淘金、吸管、被踩扁的水管）。读者记住的是画面，不是数。孟姐是唯一允许张口报账的角色（这是她的个性）。
- **人物说话前后一致**：每个人都有自己的说话逻辑，见 `01_设定/人物/声线圣经.md`。

**行业真实性红线**（详见 `00_市场/素材库.md` §7）
- 县区员工没有权限改资费、抹欠费，营销创新只能是合规组合现有方案。
- 自有员工、装维、代维、铁塔的身份边界不能混淆，主角不是什么都会的超人。
- 职级要一步步升，不能写霸道总裁式的跳级提拔。
- 素材标 ❓ 的内容不能当成真实事件写；标 🟡 的细节可以写，但不要写死具体数字。

**禁止**
- **叙述者点评和解释**：不替读者解读称呼、动作、沉默的含义（例："不叫老周，叫全名""算是默认"），不替人物担保（"这话不假"），不写说明书式的行业科普。行业知识通过人物的对话和动作带出，意味让读者自己看出来。
- 元话语（"第 X 章""前文"）、替读者总结升华、"不是 X 而是 Y"泛滥、口水词堆砌。
- 真实企业名、真实领导；把违规操作写成主角的爽点。
- 让角色知道 `追踪/上下文.md` 里标为"仅作者知道"的真相，除非 delta 里同时登记 learns 或 reveal。
